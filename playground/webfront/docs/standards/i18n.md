# i18n (traductions)

## Regle d'or

Chaque ajout UI dans le frontend doit avoir une cle de traduction.

## Convention de nommage

- Preferez une structure par feature : `conversations.list.title`, `messages.content`.
- Grouper les termes transverses dans `common`, `form`, `table`, `menu`.
- Garder les cles stables (ne pas reutiliser une cle pour un autre sens).
- Utiliser des sous-sections coherentes : `actions`, `fields`, `labels`, `errors`.

## Ou ajouter les cles

- `webfront/src/assets/i18n/fr.json`
- `webfront/src/assets/i18n/en.json`

## Usage

- Utiliser le pipe `translate` dans les templates.
- Ne pas mettre de texte hardcode dans les composants.
- Inclure aussi les labels non-visuels (aria-label, sr-only, tooltips, placeholders).
- Les labels de menu, de palette Command et de navigation doivent etre des **cles i18n** (pas du texte brut).

## Exemple (structure JSON)

```json
{
  "conversations": {
    "list": {
      "title": "Conversations",
      "description": "Messages liés chargés par IRI."
    },
    "actions": {
      "new": "Nouvelle conversation",
      "edit": "Editer"
    },
    "filters": {
      "status": "Statut"
    }
  }
}
```
